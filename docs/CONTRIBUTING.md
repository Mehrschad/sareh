# مشارکت

سره سه جور مشارکت می‌خواهد و هر سه به یک اندازه ارزشمندند:

| | چه کسی | از کجا شروع کند |
|---|---|---|
| **محتوا** | هر فارسی‌زبانی | [`CONTENT_GUIDE.md`](CONTENT_GUIDE.md) — دانشِ برنامه‌نویسی لازم نیست |
| **طراحی** | طراح، خطاط، تصویرگر | بسته‌های نماد و مسیرهای خوشنویسی، [`DESIGN.md`](DESIGN.md) |
| **کد** | Flutter یا Rust | [`ARCHITECTURE.md`](ARCHITECTURE.md) و برچسبِ `good first issue` |

## راه‌اندازی

```bash
git clone https://github.com/mehrschad/sareh
cd sareh
make bootstrap      # وابستگی‌ها + همگام‌سازیِ محتوا + قلم‌ها
make check          # همان چیزی که CI اجرا می‌کند
```

اگر Docker دارید، `.devcontainer` همه‌چیز را با یک کلیک بالا می‌آورد.

### چه چیزی برای چه کاری لازم است

| کارتان | چه بیاورید |
|---|---|
| افزودنِ واژه | چیزی — یک ویرایشگرِ متن بس است |
| کارِ روی هسته | Rust پایدار |
| کارِ روی اپ | Flutter ۳٫۲۷ به بالا |
| اجرای `make check` کامل | هر دو |

`make validate` و `make design` بی‌Flutter هم کار می‌کنند؛ اگر تنها محتوا
می‌فرستید همین دو بس است.

## گردشِ کار

۱. شاخه بزنید: `git checkout -b add-word-parmas`
۲. تغییر بدهید
۳. `make check`
۴. PR بزنید

CI روی هر PR این‌ها را می‌سنجد:

- طرح‌واره و منبعِ همه‌ی واژه‌ها
- ارجاعِ درس‌ها و قاعده‌ی «دست‌کم چهار گونه در هر منزل»
- کنتراستِ WCAG AA و نبودِ مقدارِ طراحیِ هارد‌کد
- هم‌خوانیِ `tokens.g.dart` با `tokens.json`
- `cargo test`، `cargo clippy`، `cargo fmt`
- `flutter analyze`، `flutter test`

## پیامِ کامیت

توضیح بدهید **چرا**، نه فقط **چه**. تشخیصِ «چه» از diff ممکن است؛ «چرا» نه.

```
Reject entries whose examples omit the word

The pair of sentences exists to show the swap in place. Three seeded
entries had a loan sentence that used a different word entirely, which
would have made the جای‌گزینی exercise unsolvable.
```

## سبکِ کد

**Rust** — `cargo fmt` و `cargo clippy -- -D warnings`. کامنت بنویسید که
چرایی را بگوید، نه چیستی را.

**Dart** — `flutter analyze` تمیز. سه قاعده‌ی سخت:

۱. **هیچ مقدارِ طراحیِ هارد‌کد.** رنگ، شعاع، فاصله و مدت از `tokens.g.dart`
   می‌آیند. `tools/check_design.py` این را می‌سنجد.
۲. **هر کنش برچسبِ معنایی دارد** (`Semantics`).
۳. **هر انیمیشنی باید `MediaQuery.disableAnimations` را رعایت کند.**

**زبانِ کامنت‌ها** — فارسی برای «چرا» و برای واژگانِ دامنه، انگلیسی برای
جزئیاتِ فنی. مخزن دوزبانه است و همین‌طور می‌ماند؛ سره را باید هم فارسی‌زبانی
بخواند که Rust نمی‌داند، هم Rust‌کاری که فارسی نمی‌داند.

## افزودنِ گونه‌ی تمرین

موتور آماده است. چهار گام:

۱. زیرگونه‌ی `Question` را در `lesson_controller.dart` بیفزایید
۲. سازنده‌اش را به `_build` وصل کنید — اگر داده نبود `null` برگردانید، موتور
   خودش به «گزینش» برمی‌گردد
۳. ویجتش را در `exercises.dart` بنویسید با همان قرارداد: `onAnswer(correct:)`
۴. یک شاخه به `_QuestionView` بیفزایید

هیچ فایلِ دیگری دست نمی‌خورد. اگر خورد، جای چیزی درست نیست — بگویید.

## افزودنِ بسته‌ی نماد

`design/symbol-packs/<name>/` با یک `pack.yaml` و SVGها. پیش‌فرض
(«اسطوره») باید اسطوره‌ای و بی‌طرف بماند؛ بسته‌های دیگر اختیاری‌اند. چرایی‌اش
در [`DESIGN.md`](DESIGN.md) بخش ۸ آمده.

## آیینِ رفتار

با هم مهربان باشید. سره درباره‌ی زبان است و زبان برای مردم حساس است — بحثِ
زبانی بکنید، نه بحثِ شخصی. نظرِ سره‌گرایانه‌ی تند و نظرِ محافظه‌کارانه هر دو
جا دارند؛ چیزی که جا ندارد بی‌احترامی است.

اختلافِ زبان‌شناختی را با سند حل می‌کنیم، نه با صدای بلندتر. اگر سندی نیست،
مدخل `proposed` می‌ماند تا سند پیدا شود.
